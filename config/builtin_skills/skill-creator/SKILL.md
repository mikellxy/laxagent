# 创建和维护技能

围绕用户希望复用的任务编写技能。技能用于提供特定场景的指导，不代替用户当前要求，也不增加外部操作授权。

## 文件与元数据

每个技能必须包含根目录的 `SKILL.md`，可按需包含 `scripts/`、`references/`、`assets/` 等配套文件。简单技能只需要一个 `SKILL.md`，不要生成空目录或无用模板。

`SKILL.md` 使用 UTF-8，开头是由两行 `---` 包围的 YAML 元数据，后面是 Markdown 指导：

```yaml
---
name: example-skill
description: 说明技能做什么，以及什么任务应当使用它。
allow_auto_use: true
---
```

本期只支持这三个字段，不允许重复字段：

- `name` 必填，使用小写英文字母、数字和单个连字符，不能以连字符开头或结尾，最长 64 字符；必须等于工具参数中的 `skill_name`。
- `description` 必填，非空，最长 1024 字符。明确用途与触发场景，避免吸引无关任务。
- `allow_auto_use` 是布尔值，省略时为 `true`。只有用户明确要求禁止主动使用时才设为 `false`；这种技能不出现在自动发现目录中，但可按用户指定的名称加载。

文件路径都相对于该技能根目录，不能包含 `..` 或使用符号链接。写入工具只支持 UTF-8 文本；不把二进制内容伪装成文本写入。单个 SKILL.md 最多 64 KiB，技能文件总数最多 1024，总内容最多 16 MiB。

## 创建

1. 明确技能的用途和适用边界；只有信息不足以决定内容时才向用户询问。
2. 用 `write_file` 指定 `skill_name`、`operation="write"`、相对 `path` 和完整 `content`。已有同名文件会被覆盖，操作前先核实是否存在同名技能并读取需要保留的内容。
3. 有配套文件时先写这些文件，最后写入合法的 `SKILL.md`。没有合法入口的目录尚不可加载或执行；失败后可以继续修复。
4. 调用 `load_skill` 检查完整说明与文件清单；有脚本时根据其实际用途做适当验证，不为验证而执行未经用户授权的外部操作。

技能正文只写能改变任务决策的指导。重复使用且需要确定行为的操作适合脚本；较长资料放到参考文件，正文说明何时通过 `read_file` 读取。说明依赖条件，不假设某个外部服务、账号或程序已经可用。

## 修改和删除附属文件

先 `load_skill`，再通过带 `skill_name` 的 `read_file` 阅读涉及的文件。完整替换用 `write_file`，局部替换用 `edit_file`；保留与当前任务无关的内容和使用条件。

删除附属文件使用 `write_file`：`operation="delete"`、目标相对 `path`、`content=null`。不存在的文件按已删除处理。空字符串表示保留一个空文件，不代表删除。不能删除 `SKILL.md` 或目录，不支持通过修改 `name` 改名。

写入或编辑 `SKILL.md` 前，工具会校验最终元数据；失败时原文件保留。多次文件调用不是整体事务，中断后先读取和检查，避免盲目重试。调整脚本和文档时一并检查引用是否仍然有效。

修改后重新 `load_skill`，再执行必要的脚本验证。当前对话里的技能摘要不会自动刷新，下一次任务才会使用更新后的目录；当前任务仍可按名称重新加载。用户技能副本不会因内置内容更新而被覆盖。
